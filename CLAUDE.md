# poppy-demo

Demo-tier standalone app. It plays the **personal agent** from the Personal Agent Protocol (Poppy, spec 1.0, https://personalagentprotocol.org/docs/1.0/spec): read a Company's `poppy.json`, sign in to a **real PingFederate** with a URL as the client id (CIMD) and PKCE, then call the Company API with a signed `Poppy-Session`. Real PingFederate only (owner decision 2026-10-28; exception to rules 1 and 18: the SE build is an explainer with an example run).

- Run: `./scripts/run.sh` (http://localhost:5450). Test: `npm test` (server `node --test test/*.test.js`, web vitest, repo `scripts/*.test.mjs`). Preflight: `npm run doctor`. Reset: `npm run reset`. Talk track: `npm run talk-track`. Content pack: `npm run content-pack`.
- Live run needs: a PingFederate CIMD policy for `${PAT_AGENT_BASE_URL}/client.json` whose token manager takes `client_id` from the request (docs/setup.md), the agent served over https (`PAT_TLS_CERT`/`PAT_TLS_KEY`, `PAT_BIND`, `PAT_AGENT_HOST`), and a Company serving poppy.json.
- One-command launcher: `scripts/install.sh` (curl-pipe from the public repo or run in a clone): downloads, starts and opens the lab; default is the hosted-form mock (MODE=mock), `--real` is the live run for someone's own Company and PingFederate. Docker (read-only, cap-drop ALL, 127.0.0.1 publish) or Node 26. Tests: `scripts/install.test.mjs` (dry runs only), `scripts/pingone/*.test.mjs` (in-process fake PingOne), `company/test` (incl. the e2e). The instructions live in the README between the `instructions:` markers; `npm run instructions-pdf` rebuilds `docs/Poppy-Demo-Setup.pdf` from them (needs Chrome), so edit the README and rebuild, never the PDF. `--pingone` (Node only) runs the live flow against PingOne with a REGISTERED client (no CIMD there): `scripts/pingone/setup.mjs`/`teardown.mjs` create/remove the resource, scope, web app (PRIVATE_KEY_JWT, inline ES256 jwks, PAR required) and grant from a worker's environment ID, client ID and secret (read from the terminal, never stored); `company/` is the self-contained reference Company (RS256 PingOne token + Poppy-Session checks); lab side is `server/src/registered.js` (chosen only by the discovered issuer). Real-tenant facts (2026-11-17): resource names may not contain parentheses; PingOne accepted the ES256 jwks, an http loopback redirect and PAR from the agent; an org worker may be unable to create environments or manage users.
- Core: `server/src/jose.js` (ES256, P-256 via `createECDH`), `poppy.js` (delegation + Poppy-Session signer), `oauth.js` (PKCE, `private_key_jwt`, header typ `client-authentication+jwt`), `discover.js` (typed-origin discovery), `app.js` (API), `sessions.js` (per-workspace state), `netguard.js` (typed hosts only). Story data `story.js` with `{{castBrand}}`-style tokens filled by `cast.js` (3 verticals); a test fails on an undefined token. Diagram `server/diagrams/poppy-flow.json` (diagram-studio/1).
- Sequence + movie reel on the Agent chat tab (2026-11-26): the run's steps as a lifeline sequence with a movie reel of wire-detail cards (the HITL-demo presentation). Mapped from `/api/state` by `web/src/liveSequence.js` (pure); the components are vendored byte-for-byte from ciba-approval-sequence-LAB (`components/SequenceFlowDiagram*`, `DiagramReel*`, `SequenceActorHeader*`, `components/diagram/UniqueReactFlow.jsx`, `utils/{parseSequence,diagramReel,specRefs}.js`, `hooks/{useReelSync,useFitOnResize}.js` — the last two replace this lab's older copies, which were subsets) and pinned by `scripts/sequence.sha256`, checked by `scripts/sequence-checkPin.mjs` (never hand-edit a copy; change the canonical lab first, then re-vendor and re-pin). Nothing unverified is drawn: a step that has not run is idle/ghost, an error step is the refusal text.
- API: `GET /api/info|story|sample|diagram|state|health|run-observability`, `POST /api/discover|authorize|call|reset`, `GET|POST /api/chat` (the Agent chat's live Claude agent, `server/src/chatAgent.js`: on only with `ANTHROPIC_API_KEY` and not hosted; tools reuse the discover/authorize/call handlers and take no host), plus `GET /client.json`, `/jwks.json`, `/cb`. Workspace id in `X-Workspace`.
- Rules that bite: loopback bind unless `PAT_BIND`; same-origin writes; outbound only to the two typed hosts (a permit lasts 30 s and is renewed before each call); only `.example`/`.invalid` hosts in shipped text; no `crypto.generateKeyPair('ec')` (use `createECDH`); ports 5450-5499; PF wants assertion typ `client-authentication+jwt` and `aud` = issuer; PF caches CIMD clients 5+ minutes; the agent key persists in `.data` for that reason.
- Status: proven against a local PingFederate and a local Company on 2026-10-30 (token client_id = the agent URL, 200 from `/poppy/api/v1/me`). `protected_resources` in the issuer metadata is shown as a warn check (no PingFederate setting known). Spec 1.0 (2026-11-15): sends `Poppy-Version: 1.0` on every Session request, uses `poppy_dlg` / `poppy-delegation+jwt`, and pushes the sign-in request (PAR, RFC 9126) whenever the issuer metadata lists `pushed_authorization_request_endpoint`. The Run it tab is three pages (what and why, the calls, token and session). Not exercised: refresh, revocation, device grant, DPoP, MCP. Catalog id D100 is provisional.
- Hosted guard fails closed: MODE unset/`live` is live, any other MODE is hosted; PAT_HOSTED anything but ''/0/false is hosted. The public agent name (`PAT_AGENT_HOST`) serves only GET `/client.json`, `/jwks.json`, `/cb`.
- Run observability (rule 27): `web/src/run-observability/`, the core `server/src/runObservability.js` (no imports), the readers `server/src/runObservabilityReaders.js` (this lab reads logs in Real) and `scripts/run-observability-checkPin.mjs` are vendored byte for byte from AI-DEMO-Standalone `shared/run-observability` and pinned by `web/src/run-observability/run-observability.sha256` (lab-relative paths; never hand-edit; re-vendor every file together; the pin test `scripts/run-observability.pin.test.mjs` calls `checkPin(labRoot)`). The lab's own half is `server/src/runObs.js` (stdout line, per-workspace run events, record builders) plus `web/src/components/RunObs.jsx`. Mock: only the three signings `sample.js` really did, `simulated`, stamped when built. Real: each reply the lab received is a `response` row (never `logged`; only an OAuth 400/401/403, a Company 401/403 or an issuer redirect error that is a decision (`access_denied`, `unauthorized_client`, `invalid_scope`) is `refused`, a usable 2xx `allowed`, the rest `info`; a fetch that threw is a `no-reply` info row; the lab's own security checks (RFC 9207 iss, issuer mismatch, endpoint origin) are `blocked` rows that say they are the lab's own check), plus `logged` rows read from Elasticsearch (`RUN_OBS_ES_URL`, `RUN_OBS_ES_READ_APIKEY`, read-only; the lab reads Elasticsearch only and never mounts the Docker socket). One run per record: it starts at step 1 (before the documents can fail to arrive) or at a sign-in once the last run ended, and ends at its first completed Company call; its log window ends 30 s after its last event; the person's sub is never declared as correlation. Stdout lines use `result=passed|stopped|unclear|no-reply` and never a word a shared matcher reads as a decision. Never add an event the step did not compute or receive.
- Zero real outbound calls / typed hosts only has one named exception: the vendored shared Elasticsearch reader (`runObservabilityReaders.js`) reads a loopback `RUN_OBS_ES_URL` with its own fetch, Real mode only, never Mock (see the netguard comment; loopback already passes the guard).
