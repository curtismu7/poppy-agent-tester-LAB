# TLS shims for the local compose stack

The agent container cannot reach the demo Company (`localhost:3001`) or the
PingFederate issuer shim (`local.ping-devops.com:9031`, which adds
`protected_resources`) by the names their certificates use. Two tiny TLS
pass-throughs fix that:

- `pass-tls.mjs` (company-shim): shares the agent's network namespace and
  serves `https://localhost:3001` -> `ai-demo-api-server:3001`.
- `metadata-shim.mjs` (issuer-shim): the AI-DEMO2 metadata shim (vendored),
  aliased `local.ping-devops.com` on the ai-demo network, upstream
  `ai-demo-pingfederate:9031`.

## Certificates (NOT committed)

`cert.pem`/`key.pem` (the `local.ping-devops.com` mkcert pair) and
`cert-localhost.pem`/`key-localhost.pem` (the `api.ping.demo` pair that also
covers `localhost`) are generated by mkcert and are git-ignored. Copy them
from the AI-DEMO2 checkout before `docker compose up`:

    cp ../../AI-DEMO2/local.ping-devops.com+1.pem   deploy/issuer-shim/cert.pem
    cp ../../AI-DEMO2/local.ping-devops.com+1-key.pem deploy/issuer-shim/key.pem
    cp ../../AI-DEMO2/certs/api.ping.demo+2.pem      deploy/issuer-shim/cert-localhost.pem
    cp ../../AI-DEMO2/certs/api.ping.demo+2-key.pem  deploy/issuer-shim/key-localhost.pem

Also copy the CA bundle into the agent's data volume (the server reads
NODE_EXTRA_CA_CERTS=/data/ca.pem):

    docker cp ../../AI-DEMO2/certs/ca-bundle-with-mkcert.pem \
      poppy-agent-tester-poppy-agent-tester-1:/data/ca.pem
